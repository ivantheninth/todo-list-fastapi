# Todo List with AI Assistant

A full-stack Todo application built with **FastAPI**, **React**, **PostgreSQL**, **Docker**, **Nginx**, and **GitHub Actions**.

The project combines an asynchronous Todo REST API with an AI assistant powered by the OpenAI API. The assistant can answer user messages and suggest structured Todo items. Suggested tasks are saved only after explicit user confirmation.

The application is actively being developed. Core CRUD functionality, AI integration, PostgreSQL persistence, Docker deployment, Alembic migrations, testing, and CI/CD are implemented.

User authentication is currently in progress and includes registration, password hashing, login, JWT access tokens, and a current-user dependency.

---

## Features

### Todo API

- Create tasks
- Bulk task creation
- Retrieve all tasks
- Retrieve a task by ID
- Full updates with `PUT`
- Partial updates with `PATCH`
- Delete tasks
- Optional notes
- Completed / active state
- Async database operations

### AI Assistant

- OpenAI API integration with `AsyncOpenAI`
- Structured AI responses
- Todo suggestions generated by AI
- Pydantic validation
- Invalid JSON and response-structure handling
- LLM error handling with `503 Service Unavailable`
- AI suggestions require explicit confirmation before being saved

### Authentication — Work in Progress

Currently implemented:

- User registration
- Unique user emails
- Password hashing with `pwdlib`
- Password verification
- Login
- JWT access-token generation
- JWT decoding
- Bearer authentication
- `get_current_user` dependency
- Initial protection of `GET /tasks`

Authentication is not yet fully integrated across all Todo operations.

Tasks are also not yet associated with individual users.

## Architecture

```text
Browser
   |
   v
 Nginx
   |
   +-------------------+
   |                   |
   v                   v
Frontend            FastAPI
                       |
              +--------+--------+
              |                 |
              v                 v
          PostgreSQL         OpenAI API
```

Nginx acts as the public entry point and routes requests between the frontend and backend.

PostgreSQL stores application data, while the FastAPI backend communicates with the OpenAI API for AI assistant functionality.

## AI Assistant Flow

```text
User message
    |
    v
POST /chat
    |
    v
FastAPI
    |
    v
LLMService
    |
    v
OpenAI API
    |
    v
Structured response
    |
    +---- answer
    |
    +---- suggested tasks
              |
              v
       User confirmation
              |
              v
       POST /tasks/bulk
              |
              v
          PostgreSQL
```

The AI assistant does not write directly to the database.

Tasks suggested by the model are persisted only after user confirmation.

The assistant is currently stateless and does not preserve conversation history or read existing Todo records.

### Login

```text
POST /auth/login
        |
        v
Find user
        |
        v
Verify password
        |
        v
Create JWT
        |
        v
Return access token
```

### Protected Request

```text
Request
   |
   v
Bearer token
   |
   v
decode_access_token()
   |
   v
get_current_user()
   |
   v
Protected endpoint
```

Passwords are stored as hashes rather than plaintext.

JWT access tokens contain the user ID and expiration time.

## API

### General

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Application status |
| `GET` | `/health` | Health check |

### Authentication

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/auth/register` | Register a user |
| `POST` | `/auth/login` | Login and receive JWT |

Example registration request:

```json
{
  "email": "user@example.com",
  "password": "example-password"
}
```

Example login response:

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer"
}
```

### Tasks

| Method | Endpoint | Description | Auth |
|---|---|---|---|
| `GET` | `/tasks` | Get all tasks | Required |
| `GET` | `/tasks/{task_id}` | Get task | No |
| `POST` | `/tasks` | Create task | No |
| `POST` | `/tasks/bulk` | Create multiple tasks | No |
| `PUT` | `/tasks/{task_id}` | Replace task | No |
| `PATCH` | `/tasks/{task_id}` | Update task | No |
| `DELETE` | `/tasks/{task_id}` | Delete task | No |

Authentication for the remaining task endpoints is planned.

### AI

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/chat` | Send a message to the AI assistant |

Example:

```json
{
  "message": "Create a study plan for learning FastAPI"
}
```

Possible response:

```json
{
  "answer": "Here is a simple study plan.",
  "tasks": [
    {
      "title": "Learn FastAPI routing",
      "note": "Practice the main HTTP methods"
    },
    {
      "title": "Study dependency injection",
      "note": "Practice Depends and database dependencies"
    }
  ]
}
```

Interactive API documentation is available at `/docs`.

## Alembic Migrations

The project uses Alembic for database schema migrations.

Check the current migration:

```bash
cd backend
alembic current
```

View history:

```bash
alembic history
```

Apply migrations:

```bash
alembic upgrade head
```

Create a new migration:

```bash
alembic revision --autogenerate -m "migration description"
```

Then apply it:

```bash
alembic upgrade head
```
